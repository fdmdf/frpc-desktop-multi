# 构建与发版

## 环境

| 组件 | 版本要求 | 用途 |
| --- | --- | --- |
| JDK | 17+（推荐 21） | Gradle / Kotlin 编译 |
| Android SDK | platform 36、build-tools 36.0.0 | 应用构建 |
| Go | 1.26+ | 重建 frpc 引擎（可选） |
| Node.js | 20+ | 重建 Web 控制台（可选，仓库已带产物） |

## 本地构建

```bash
echo "sdk.dir=$HOME/Android/Sdk" > local.properties

# 单测（shared 双端 + 应用）
./gradlew :shared:jvmTest :shared:testDebugUnitTest :androidApp:testDebugUnitTest

# Debug 包
./gradlew :androidApp:assembleDebug
# 产物：androidApp/build/outputs/apk/debug/androidApp-debug.apk

# Release（未签名）
./gradlew :androidApp:assembleRelease
```

## 签名

Release 通过环境变量注入签名，未配置时产出未签名 APK：

```bash
keytool -genkeypair -v -keystore release.jks -alias frpc \
        -keyalg RSA -keysize 2048 -validity 10000

KEYSTORE_PATH=$PWD/release.jks \
KEYSTORE_PASSWORD=你的密码 \
KEY_ALIAS=frpc \
KEY_PASSWORD=你的密码 \
./gradlew :androidApp:assembleRelease
```

## 重建 frpc 引擎

```bash
# 默认按 androidApp/src/main/assets/frpc/VERSION 的版本编译
bash scripts/build-frpc.sh

# 指定版本
FRP_VERSION=v0.72.0 bash scripts/build-frpc.sh

# 额外编译 x86_64（模拟器，需 NDK）
SKIP_X86_64=0 bash scripts/build-frpc.sh
```

脚本做的事：

1. 通过 `goproxy.cn` 拉取 frp 指定版本的源码
2. 准备 `web/frpc/dist`（优先用仓库内 `scripts/frpc-web-dist` 官方控制台产物）
3. `CGO_ENABLED=0 GOOS=android GOARCH=arm64 go build -trimpath -ldflags "-s -w" -tags frpc`
4. 输出 `androidApp/src/main/jniLibs/arm64-v8a/libfrpc.so` 并写 `assets/frpc/VERSION`

> 注意：引擎必须以 `libfrpc.so` 命名并放在 jniLibs —— Android 10+ 只允许从 `nativeLibraryDir` 执行二进制。

## 重建 Web 控制台（可选）

```bash
cd <frp 源码>/web/frpc
npm install          # 或 npm i --registry=https://registry.npmmirror.com
npm run build-only   # vite 构建（跳过 vue-tsc 类型检查）
# 把 dist/ 拷回 scripts/frpc-web-dist/
```

## 自动发版（GitHub Actions）

`.github/workflows/release.yml`：

| 触发 | 行为 |
| --- | --- |
| push `v*` tag | 按 tag 版本发布 |
| 手动触发（workflow_dispatch） | 填版本号，四平台一起构建并发布 |

一次发版产出：

| 平台 | 产物 |
| --- | --- |
| Windows x64 | `FrpcDash-<ver>-windows-x64-setup.exe`（jpackage + WiX 安装程序）、`...-windows-x64.zip`（便携版） |
| Linux x64 | `...-linux-x64.tar.gz`、`...-linux-x64.deb`（环境允许时附 AppImage） |
| macOS arm64 | `...-macos-arm64.dmg`、`...-macos-arm64.tar.gz` |
| Android arm64 | `...-android-arm64.apk` |

流程：各 runner 编译自己平台的 frpc → 跑单测 → 打包 → 汇总产物 → 创建 Release。

### 需要的 Secrets

| Secret | 内容 |
| --- | --- |
| `KEYSTORE_BASE64` | `base64 -w0 release.jks` |
| `KEYSTORE_PASSWORD` | keystore 密码 |
| `KEY_ALIAS` | 别名 |
| `KEY_PASSWORD` | 别名密码 |

未配置时产出未签名 APK，无法直接安装。

`ci.yml`：每次 push / PR 跑 shared 与 Android 单测、Windows 桌面端编译 + 冒烟、Ubuntu 上的八协议端到端测试。

## 发布到 GitHub

仓库内提供一键脚本：

```bash
bash scripts/publish.sh <你的GitHub用户名> <仓库名>
```

脚本会：替换 README 中的 `OWNER/REPO` 占位 → 初始化 git 与首次提交 → 创建/关联远端 → 推送 → 同步 Wiki（`docs/wiki` → wiki 仓库）。

若不想用脚本，手动步骤：

```bash
git init && git add -A && git commit -m "feat: initial commit"
git branch -M main
git remote add origin git@github.com:<owner>/<repo>.git
git push -u origin main
```

Wiki 同步：

```bash
git clone https://github.com/<owner>/<repo>.wiki.git wiki
cp docs/wiki/*.md wiki/
cd wiki && git add -A && git commit -m "docs: sync wiki" && git push
```
