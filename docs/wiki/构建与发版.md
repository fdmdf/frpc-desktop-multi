# 构建与发版

## 环境

| 组件 | 版本要求 | 用途 |
| --- | --- | --- |
| Rust | 1.85+（stable） | 核心层与 Tauri 外壳 |
| Node.js | 20+ | 前端（Vue 3 / Vite） |
| Go | 1.21+ | 重建 frpc 引擎（可选） |
| Android SDK | platform 36、NDK 27.2 + JDK 17 | 仅打 APK 时需要 |

## 本地构建

```bash
# 引擎（桌面：输出到 tauri/app/src-tauri/resources/engine）
bash scripts/build-frpc.sh desktop
# Android：输出到 tauri/engines/android/jniLibs
bash scripts/build-frpc.sh android

# 核心层单测（88 项）
cargo test --manifest-path tauri/Cargo.toml -p frpc-core

# 桌面端（Windows 产出 NSIS exe 与 msi）
cd tauri/app/ui && npm ci && npm run build
cd tauri/app && ui/node_modules/.bin/tauri build
```

Android：

```bash
export ANDROID_HOME=$HOME/Android/Sdk
export NDK_HOME=$ANDROID_HOME/ndk/27.2.12479018
bash scripts/tauri-android-setup.sh        # 生成 gen/android 并打 gradle 补丁
cd tauri/app && ui/node_modules/.bin/tauri android build --apk --target aarch64
```

> Windows 上 Tauri 创建 jniLibs 符号链接需要管理员或开发者模式；
> 未开启时按 `scripts/tauri-android-setup.sh` 末尾注释的绕过流程手工放 `.so` 再跑 gradle。

## 签名

桌面端：macOS 目前未签名（首次启动需在「系统设置 → 隐私与安全性」允许）；Windows 未做代码签名。

Android：CI 每次发版生成**临时** keystore 并签名，签名校验失败则工作流终止，不会发出装不上的产物。
因为是临时密钥，APK 不支持"覆盖升级"式的一致性校验——需要长期稳定签名时，把 keystore 放进仓库 secret
并改 `.github/workflows/tauri.yml` 的 `Sign APK` 步骤即可。

本地签名校验：

```bash
"$ANDROID_HOME/build-tools/34.0.0/apksigner" verify --print-certs \
  frpc-desktop-multi-1.4.0-arm64.apk
```

## 重建 frpc 引擎

```bash
# 默认 FRP_VERSION=v0.71.1
bash scripts/build-frpc.sh desktop
bash scripts/build-frpc.sh android

# 指定版本
FRP_VERSION=v0.72.0 bash scripts/build-frpc.sh desktop

# 额外编译 x86_64（模拟器，需 NDK）
SKIP_X86_64=0 bash scripts/build-frpc.sh android
```

脚本做的事：

1. 依次尝试 `goproxy.cn` / `proxy.golang.org` 拉取 frp 指定版本源码
2. 准备 `web/frpc/dist`（优先用仓库内 `scripts/frpc-web-dist` 官方控制台产物）
3. `CGO_ENABLED=0 GOOS=android GOARCH=arm64 go build -trimpath -ldflags "-s -w" -tags frpc`
4. 输出 `tauri/engines/android/jniLibs/arm64-v8a/libfrpc.so`

> 注意：Android 引擎必须以 `libfrpc.so` 命名并放在 jniLibs —— Android 10+ 只允许从 `nativeLibraryDir` 执行二进制。

## 自动发版（GitHub Actions）

`.github/workflows/tauri.yml`：

| 触发 | 行为 |
| --- | --- |
| push `v*` tag | 核心层测试 + 三平台桌面包 + Android APK，全部挂到该 tag 的 Release |
| push `main` / `dev` / `tauri-rewrite`、PR | 只跑核心层测试与桌面包（不发版） |
| 手动触发（workflow_dispatch） | 同上，但 tag 才会上传 Release 资产 |

一次发版产出：

| 平台 | 产物 | 大小 |
| --- | --- | --- |
| Windows x64 | `frpc-desktop-multi_<ver>_x64-setup.exe`、`..._x64_en-US.msi` | 7.1 MB / 9.5 MB |
| Linux x64 | `..._amd64.deb`、`..._amd64.AppImage` | 10 MB / 84 MB |
| macOS arm64 | `..._aarch64.dmg` | 8.7 MB |
| Android arm64 | `frpc-desktop-multi-<ver>-arm64.apk` | 10.5 MB |

流程：各 runner 编译自己平台的 frpc 引擎 → 核心层 fmt + 单测 → 前端构建 → Tauri 打包 →
`softprops/action-gh-release` 追加到同一个 Release。Android job 额外装 NDK、跑
`scripts/tauri-android-setup.sh`、用临时 keystore 签名。

发版步骤（维护者）：

```bash
git tag -f v1.4.0 -m "v1.4.0"
git push -f origin v1.4.0
```
