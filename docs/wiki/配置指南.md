# 配置指南

App 的配置界面与 `frpc.toml` 一一对应，字段的可见性与校验规则都以 frp 源码
（`pkg/config/v1` + `pkg/config/v1/validation`）为准。本文按区块说明，末尾给出各代理类型的示例。

## 全局

| 界面名称 | 对应 frpc.toml | 说明 |
| --- | --- | --- |
| 配置名称 | 无 | 只在本机区分多份配置，不写进 frpc.toml |
| 服务器地址 / 端口 | `serverAddr` / `serverPort` | frps 地址。**kcp/quic 要填服务端对应的 `kcp_bind_port` / `quic_bind_port`**（见[协议兼容性](协议兼容性.md)） |
| 代理名前缀（user） | `user` | 代理在 frps 上的最终名变成 `{user}.{代理名}`；留空则不加前缀 |
| 客户端标识（clientID） | `clientID` | 可选，frps 面板用来区分设备 |
| 首次登录失败就退出 | `loginFailExit` | 默认关闭：连不上就持续重连（切换网络友好）。frp 自身默认是 `true`，App 按移动场景改成了 `false` |
| STUN 服务器 | `natHoleStunServer` | 只有 xtcp 打洞用到。留空用 frp 默认 `stun.easyvoip.com:3478`，该地址在国内经常超时 |

## 认证

| 界面名称 | 对应 | 说明 |
| --- | --- | --- |
| 认证 Token | `auth.token` | 必须与 frps 的 `auth.token` 完全一致（注意首尾空格） |

> 认证方式固定为 `token`。frp 的 `oidc` 还要填 `clientID`、`tokenEndpointURL` 等一组字段，
> App 不提供这些输入框，需要时导出 `frpc.toml` 手动补。

## 状态监控（本机接口）

| 界面名称 | 对应 | 说明 |
| --- | --- | --- |
| 开启状态接口（webServer） | `webServer` 段 | 开启后 App 能读取代理在线状态、**实际分配端口**、CPU/内存；关闭则状态只能靠日志推断 |
| 监听地址 / 端口 | `webServer.addr` / `port` | 默认 `127.0.0.1:7400`，只监听本机，不对外暴露；同机多份配置要各用不同端口 |
| 面板用户名 / 密码 | `webServer.user` / `password` | 浏览器打开状态页要登录，默认 `admin/admin`，建议修改 |

> 安全提示：不要把监听地址改成 `0.0.0.0`，否则同网段任何人都能读取你的代理信息。

## 传输

| 界面名称 | 对应 | 说明 |
| --- | --- | --- |
| 连接协议 | `transport.protocol` | `tcp`（默认）/`kcp`/`quic`/`websocket`/`wss` |
| TCP 多路复用 | `transport.tcpMux` | 默认开，需与服务端一致 |
| 预连接数 | `transport.poolCount` | 预建连接降低首包延迟。**frp 的默认值是 1**，写 0 会被 `Complete()` 改回 1，不是「不预建」 |
| 启用 TLS | `transport.tls.enable` | frp ≥ 0.50 默认开；服务端不支持时关闭 |
| 代理服务器 URL | `transport.proxyURL` | 走 http/socks5 代理连 frps，仅 `tcp` 协议有效 |
| UDP 包大小 | `udpPacketSize` | 影响 udp/sudp，默认 1500，需与服务端一致 |

## 日志

| 界面名称 | 说明 |
| --- | --- |
| 日志级别 | `trace`/`debug`/`info`/`warn`/`error`，排查问题用 `debug`。日志固定输出到 console，由 App 采集后展示 |

## 代理规则

带 `*` 为必填；其余字段只在对应类型下出现（frp 按类型严格解码，多余字段会让 frpc 启动失败）。

### TCP / UDP

```
名称 *      ssh
类型 *      TCP
本地地址 *  127.0.0.1
本地端口 *  22
远程端口    6001        # 留空或 0 = frps 随机分配
```

UDP 适合 DNS、游戏等。两者的「对外入口」都是 frps 上的端口。

### HTTP / HTTPS（需要 frps 配 vhost 端口）

```
名称 *      web
类型 *      HTTP
本地地址 *  127.0.0.1
本地端口 *  80
子域名       web01               # 只填一级名字，不能带 . 或 *
自定义域名   web01.example.com   # 与子域名至少填一个，可以都填
路由路径     /, /pic            # 仅 http
HTTP 账号 / 密码  admin / admin  # 仅 http、tcpmux
按 HTTP 账号路由  user1          # 仅 http、tcpmux
Host 头重写  nas.local           # 仅 http
```

- 需 frps 配置 `vhostHTTPPort`（子域名还需要 `subdomainHost`）
- **HTTPS 代理是 TLS 透传**：本地服务必须自己支持 HTTPS，frps 只按 SNI 路由
- HTTPS 没有 `httpUser` / `httpPassword` / `locations`，界面上也不会出现；它独有 `PROXY Protocol`（v1/v2），
  用来把真实来源 IP 透传给本地服务

### STCP / SUDP / XTCP（私密通道）

```
名称 *      secret_ssh
类型 *      STCP
本地地址 *  127.0.0.1
本地端口 *  22
私密密钥 *  your-secret
允许访问的账号  user2   # 留空=仅本 user；* = 允许所有 user
```

访问端需要配置**访问者**：

```
访问者名称 *  secret_ssh_visitor
类型 *        STCP
对方代理名 *  secret_ssh      # 只填代理名，不要带对方前缀
对方设备前缀   laptop        # 留空 = 用本机 user 作为前缀
私密密钥 *    your-secret
监听地址      127.0.0.1
监听端口 *    9000           # 0 会被 frp 拒绝；-1 = 不监听（sudp 不支持）
```

> 名称拼接规则来自 `pkg/naming/names.go`：`serverUser` 非空用它，留空用本机 `user`，
> 最终名 = `前缀.代理名`。所以「代理名」里带上点会被再拼一次前缀，必然查不到——界面会实时显示
> 最终查找的名字，并给「按此改」一键拆开。

之后访问本机 `127.0.0.1:9000` 即走隧道。SUDP 为 UDP 版本，XTCP 会先尝试 P2P 直连。

xtcp 访问者额外有：

| 界面名称 | 对应 | 说明 |
| --- | --- | --- |
| 保持隧道 | `keepTunnelOpen` | 持续尝试打通并保持 P2P 隧道，代价是常驻流量 |
| 打洞失败转交给 | `fallbackTo` | 填另一个**访问者名称**（通常是指向同一代理的 stcp 访问者），打洞超时后数据改走 frps |
| 等待时长 | `fallbackTimeoutMs` | 毫秒，留空由 frpc 用默认 1000 |

> `keepTunnelOpen` / `fallbackTo` / `fallbackTimeoutMs` 在 frp v1 里只属于 **xtcp 访问者**；
> stcp/sudp 访问者带上会让 frpc 报 `unknown field` 直接退出。App 按类型自动清理。

### TCPMUX（需要 frps 配 tcpmux 端口）

```
名称 *      mux
类型 *      TCPMUX
多路复用器 * httpconnect     # frp 只接受这一个值
本地地址 *  127.0.0.1
本地端口 *  10701
自定义域名  tunnel1
```

需 frps 配置 `tcpmuxHTTPConnectPort`。

## 常见误填（会直接让 frpc 起不来）

| 现象 | 原因 |
| --- | --- |
| `bind port is required` | 访问者 `bindPort` 写成 0。不监听要填 `-1` |
| `'.' and '*' are not supported in subdomain` | 子域名里带了点或星号，通配应写在自定义域名里 |
| `not support multiplexer` | tcpmux 的 `multiplexer` 不是 `httpconnect` |
| `unit not support` | 带宽限制没带单位，必须写成 `1MB` / `512KB` |
| `unknown field` | 该类型不支持这个字段（多为导入外部 toml 带进来的） |

## 导入 / 导出

- **导出**：配置列表 → 卡片右上角菜单 → 导出，得到标准 `frpc.toml`，可给其它 frpc 使用。三种落地方式：
  - **保存到文件（.toml）**：调起系统文件选择器，可存到「下载」「文档」或任意目录
  - **分享**：交给其它 App（微信、邮件、网盘等）
  - **复制到剪贴板**：临时粘贴到聊天窗口
- **导入**：配置列表底部「导入」（没有配置时，空状态卡片里也有入口），选择 `.toml` 文件

> 文件选择器按 `*/*` 过滤：`.toml` 在 Android 上没有登记标准 MIME，若按 `text/*` 过滤会在选择器里被隐藏，看起来像"无法选中文件"。

导入时会：

- 忽略未建模字段（plugin / healthCheck / annotations / metadatas 等）
- **自动清理该代理类型不支持的字段**（例如 sudp 带 `remotePort` 会让 frpc 启动失败，导入时会去掉）
- 若这是库里唯一的一份配置（或此前还没设默认），**自动设为默认配置**

## 多配置

支持保存多个服务器档案，主页顶部可切换；「设为默认」的配置用于开机自启。

## 运行中不能改配置，先停止

配置一旦运行就被 frpc 使用，改动不会生效，因此两端都禁止编辑运行中的配置：

- 配置列表里，运行中的那一份编辑入口变灰，并提示「运行中，停止后才能编辑」
- 直接进入编辑页（深链接 / 返回栈）只会看到「配置正在运行」+「停止运行」「返回列表」

要改配置的流程：主页点「停止」→ 配置页编辑并保存 → 回主页「启动」。

如果只是想让 frpc 重读一次当前配置（例如换了 frps 端的东西），用主页的「重载配置」即可，它会走状态接口的 `api/reload`；状态接口端口变化时自动改为整进程重启。
