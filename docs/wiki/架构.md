# 架构

## 总览（v1.4.0 起：Tauri 2 + Rust 核心层 + Vue 3）

```
┌────────────────────── tauri/crates/frpc-core（纯 Rust，不依赖 Tauri）────────────────┐
│  model/       FrpcConfig · ProxyConfig · VisitorConfig · ProxyType                   │
│  toml/        toml_edit 无损读写（保留未知字段与点号键，导入不再静默丢字段）            │
│  validate/    ConfigValidator（端口范围/必填/类型字段兼容）                            │
│  admin/       reqwest + rustls，Basic Auth 拉 /api/status                            │
│  logs/        日志行解析与环形缓冲                                                    │
│  metrics/     sysinfo 采样（桌面）/ PowerShell（Core 不可用时的兜底）                  │
│  net/         端口占用探测                                                            │
│  store/       档案与设置的 JSON 原子写                                                │
│  supervisor/  frpc 子进程状态机 + 日志采集 + 指数退避自动重启                          │
└───────────────────────────────────┬─────────────────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼─────────────────────────────────────────────────┐
│ tauri/app/src-tauri    命令桥（invoke）+ 托盘 / 单实例 / 开机自启（桌面专属，按 target 门控）│
│ tauri/app/ui           Vue 3 + Pinia + vue-i18n 界面，桌面与 Android 共用同一份代码     │
│ tauri/engines/android  Android 引擎产物（jniLibs，构建生成，不入库）                    │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

> 旧版（v1.3.x）是 Kotlin Multiplatform + 两套 Compose UI，代码已归档到 `archive/kotlin-legacy` 分支。

## 关键设计取舍

### 1. 引擎放在 jniLibs（而不是 assets 拷贝到 filesDir）

Android 10+ 禁止从应用数据目录 `execve`（W^X）。1.0.0 把二进制拷到 `filesDir/bin` 后真机直接 `error=13 Permission denied`。

jniLibs 是系统认可的 native 库落点：安装时解压到 `/data/app/.../lib/arm64/`，进程可直接执行。代价是必须命名为 `lib*.so`，且需要 `extractNativeLibs=true`（对应 gradle 的 `useLegacyPackaging`）。

### 2. 代理状态「双源」

| 来源 | 优点 | 缺点 |
| --- | --- | --- |
| 状态接口 `webServer`（`/api/status`） | 精确状态、实际分配端口、错误原因 | 需开启；明文 HTTP 需放行回环 |
| 日志推断（`proxy added` / `start proxy success` / `start error`） | 无需额外配置，一定有 | 拿不到实际端口，控制连接断开时状态清空 |

实现上先取接口数据，缺失时用日志推断，两者都没有时显示「未知」而不是「离线」——避免误导。

### 3. TOML 编解码的两个坑

- **点分键**：`[[proxies]]` 内的 `transport.x = y`，朴素解析会为每个键生成一个同名子表导致丢字段。改用 `toml_edit` 做无损往返，导入时只剔除本类型不支持的字段，其余保留。
- **frp 按类型严格解码**：例如 sudp 带 `remotePort` 会让 frpc 直接退出。导入和切换代理类型时调用 `sanitized_for_type()` 清理，校验器再兜一层。

### 4. 进程级共享 tokio 运行时

Supervisor 的 `start()` 可能在 Tauri 命令线程（**没有 tokio 上下文**）被调用，早期实现在这里 `tokio::spawn` 会 panic（表现为"点启动就闪退"）。改为进程级 `OnceLock<Runtime>` 共享运行时，永不 drop，并留了 `start_works_without_tokio_context` 回归测试。

崩溃重启用指数退避（2s → 60s，可配 `max_restarts`），避免「启动-崩溃」死循环。

### 5. 不做的事

- 核心层不依赖 Tauri：能独立 `cargo test`，迁移期的 Kotlin 用例可直接对拍
- 桌面专属能力（托盘/单实例）按 target 门控，Android 构建不携带
- 不在 UI 层直接做 IO：界面只通过 12 个 Tauri 命令与事件和核心层通信

## 测试策略

| 层次 | 位置 | 覆盖 |
| --- | --- | --- |
| 核心层单测 | `tauri/crates/frpc-core/src/**` 内联 `#[cfg(test)]` | TOML 往返、真实 frp 配置解析、校验规则、类型字段兼容、退避计算、生命周期（假引擎） |
| 集成测试 | `tauri/crates/frpc-core/tests/` | 完整 frpc 示例配置的解码 / 再编码不丢字段 |
| 端到端 | `scripts/tauri-e2e.sh` → `--test e2e_protocols` | 八协议 verify + 真实建隧道回环（需本地 frps / frpc 引擎） |

CI（`.github/workflows/tauri.yml`）每次推送都跑 `cargo fmt --check` + 核心层测试。

## 引擎构建

`scripts/build-frpc.sh`：拉取 frp 源码 → 准备 Web 控制台产物 →
桌面 `GOOS=windows|linux|darwin`、Android `CGO_ENABLED=0 GOOS=android GOARCH=arm64`，
均 `go build -trimpath -ldflags "-s -w" -tags frpc` → 输出引擎 + `VERSION`。
